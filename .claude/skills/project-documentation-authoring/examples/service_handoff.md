# 客服政策问答：把待确认问题交给能够作决定的人

> 说明性项目提案。案例中的流程为拟定方案，不表示任何企业已采用此政策。

客服在处理退款咨询时可能同时看到两份含义不同的政策说明。直接选择更新时间较新的页面，无法证明它适用于该订单。项目希望先帮助客服找到适用条件及缺口，再把必要问题交给政策负责人确认。

首期功能是在授权知识范围内，给出候选政策的适用产品、地区、订单条件和来源，说明冲突会改变什么回答。已经明确规则时，客服可以据此形成回复草稿；关键适用条件不清时，系统保留候选解释，并给政策负责人一个可以直接回答的问题。

例如，两份材料对“购买后 30 天内”的起点分别使用付款和签收。需要确认的是该产品的正式起点及适用例外，回答将改变这笔订单是否处于申请窗口。该示例只说明业务歧义，具体期限和规则仍须以项目材料为准。

选择先做草稿与确认交接，是为了让政策决定保留在其负责人手中。首期完成并不包含自动退款或对外发送。政策负责人确认后，维护者把有来源的解释更新到既有知识入口，使后续客服能够找到相同依据；知识更新不能被视为自动执行退款的授权。

验收检查三个结果：条件明确时能解释采用哪条政策及理由；条件冲突时能指出对当前订单的影响和具体问题；确认后能回到准确政策依据。回复质量与真实退款结果分别验证，不能凭草稿生成成功宣布业务处理完成。

这个例子的对象是订单、政策和客服交接，写作方法仍然从业务问题进入，连接条件、选择、动作和结果。
