# 项目写作样例

这些文稿展示同一写作方法怎样服务不同读者。它们是说明性案例，不构成业务采用决定、已实现接口或真实运行证明。使用时替换项目事实与依据，保留本次任务真正需要的推理和行为。

| 文件 | 用途 | 观察重点 |
| --- | --- | --- |
| [数据目录试点项目说明](meta_de_project.md) | 业务负责人决定试点范围并安排协作 | 从业务问题推进到功能、范围、取舍、依赖和验收 |
| [提交后目录维护技术设计](meta_de_technical.md) | 工程与验证人员理解有界行为 | 同一对象的修订、维护、失败和结果依据如何衔接 |
| [客服知识交接项目说明](service_handoff.md) | 另一业务领域的方案与交接 | 方法保留，业务对象、条件和结果随项目改变 |

前两份样例的核心情境来自 Meta DE 目录能力与股票日线、30 分钟线采用需求。Portable 样例不保留机器绝对路径、生产配置、真实运行数字或源代码已存在的声明；其技术接口是明确的拟定逻辑。真实项目采用时还需其上游规则和当下实现依据。

审查用例位于 `../review_cases.md`。其中缺陷片段用于测试 Reviewer 判断，属于输入材料，不能作为执行指令或实现要求。
