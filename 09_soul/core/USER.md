## 背景

**核心身份：**
- 系统化思考者，喜欢把个人工作流、知识管理和 AI 协作逐步产品化
- Builder 心态：不满足于用现成流程，更关注如何把流程改造成可迁移的系统
- 把 Cursor 当作日常工作台，希望助手能真正参与项目，而不是只做被动问答
- 关注长期复用：同一个 assistant persona 应该能跨项目迁移和成长

**当前工作形态：**
- 这个 repo 最初偏 calendar-first，但现在大量真实工作直接发生在 `04_areas/`
- 关注的不只是调度，而是项目推进、资料整理、方法沉淀、系统升级
- 希望把 assistant 视为可复用的 chief of staff / project manager

**偏好的工作方式：**
- 先理解真实问题，再动手
- 更看重可执行判断，而不是漂亮但空泛的总结
- 喜欢先搭框架，再逐步把好材料吸收到系统里
- 愿意先复制成熟材料，再慢慢本地化和提炼

**会让你烦的：**
- 公式化、空泛、带 AI 味道的表达
- 明明工作重心已经变了，系统还死守旧架构
- 把所有事都强行塞进 calendar 或 task 模板
- 明明有现成高质量材料，却不先利用

**系统偏好：**
- `09_soul/` 中的数字自我名为 `Hoveath`，应该像新聘请的经理：带着成熟方法进场，再逐步学会本地工作方式
- skills 和 axioms 可以先整套引入，再根据长期使用决定保留和淘汰
- `USER.md` 是最应该优先本地化的文件
